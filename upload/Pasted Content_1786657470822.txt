# برومبت موحّد وكامل لبناء نظام «سما اليمن للسفريات والسياحة»

> **هذا النص هو برومبت واحد مستقل وجاهز للنسخ.** لا تعتمد على أي ملحق أو برومبت سابق، ولا تحذف أو تختصر أو تدمج أي خدمة أو حقل أو قائمة منسدلة مذكورة فيه. عند وجود تعارض بين التوجيهات، تكون الأولوية بالترتيب: حماية البيانات والصلاحيات، ثم ترتيب حقول الخدمات وقيم القوائم المنسدلة، ثم قواعد الفوترة والحساب، ثم تصميم الواجهة.

---

## 1. الدور والمهمة ونطاق المشروع

تصرّف كمهندس برمجيات معماري (**Solutions Architect**) وخبير تقني ومنتجات رقمية بخبرة لا تقل عن 15 سنة في بناء الأنظمة الداخلية لمكاتب السفر والسياحة والحج والعمرة في الأسواق العربية والخليجية. مهمتك هي بناء نظام إداري داخلي متكامل باسم **سما اليمن للسفريات والسياحة**. النظام مخصص لموظفي المكتب وإدارته فقط، وليس موقعاً تسويقياً أو تطبيقاً للعملاء.

يغطي النظام خدمات الحج والعمرة، الجوازات، تذاكر الطيران، النقل الدولي والمحلي، التأشيرات، الشحن والتخليص الجمركي، المعاملات الخاصة، الحجوزات الفندقية، التأمينات، العملاء، الموظفين، الوكلاء والشركات، الإيرادات والمصروفات والمدفوعات والفواتير والإحصائيات والتدقيق.

يجب أن يكون النظام رسمياً، هادئاً، سريعاً وسهل الاستخدام. لا تخلط البيانات أو تجمع خدمات مختلفة في نموذج واحد. كل خدمة لها شاشة ونموذج وسجل مستقلان، مع الحفاظ الحرفي على حقولها وترتيبها وقوائمها كما وردت في هذا البرومبت.

اللغة الافتراضية هي العربية مع دعم كامل لاتجاه الكتابة من اليمين إلى اليسار (**RTL**). تُكتب التواريخ والأرقام بالأرقام الإنجليزية، مثل `2026-08-06` و`1234`، ولا تستخدم الأرقام الهندية. يجب دعم اللغة الإنجليزية من الإعدادات، وعند تبديلها يتحول اتجاه الواجهة تلقائياً إلى **LTR** دون كسر التخطيط.

## 2. المبدأ الحاكم للتنفيذ

أنشئ نظاماً حقيقياً قابلاً للصيانة والتوسع، لا واجهات شكلية أو بيانات وهمية فقط. افصل الواجهة الأمامية عن الخلفية، وطبّق الصلاحيات في الخلفية في كل طلب، وليس بإخفاء الأزرار في الواجهة فقط. لا تُظهر كلمات مرور أو بيانات اعتماد أو إجابات استرداد أو أرقام وثائق حساسة كاملة في الواجهات أو التقارير أو سجلات التدقيق.

كل سجل مالي أو خدمة أو فاتورة أو دفعة أو تغيير صلاحية يجب أن يكون قابلاً للتتبع. يجب منع ضياع البيانات، ومنع التكرار المالي، ومنع تضارب أرقام الفواتير أو السندات عند تنفيذ أكثر من عملية في وقت واحد.

## 3. البنية التقنية الإلزامية

استخدم البنية التالية ما لم يوجد سبب هندسي موثق وضروري لتعديل جزء تقني محدد:

| الطبقة | التقنية أو القاعدة المطلوبة |
| --- | --- |
| الواجهة الأمامية | React مع Next.js وTypeScript، ودعم RTL كامل. استخدم مكونات قابلة لإعادة الاستخدام ونظام تصميم موحّد. |
| الواجهة الخلفية | NestJS مع TypeScript. استخدم Dependency Injection، وطبقات واضحة للخدمات والمستودعات والتحقق والصلاحيات. |
| واجهة البرمجة | جميع المسارات تحت `/api/v1/...` مع API Versioning، والتحقق من الدور والصلاحية في كل Endpoint. |
| قاعدة البيانات | **PostgreSQL 16 أو إصدار مدعوم أحدث**، وهي قاعدة البيانات الإنتاجية الوحيدة. لا تستخدم SQLite أو MongoDB أو Firebase في الإنتاج. |
| توليد الفواتير والتقارير | PDF مولّد من الخادم بقالب موحّد يدعم العربية وRTL، مع تصدير Excel منظم يحافظ على ترتيب الأعمدة. |
| المصادقة | جلسات أو رموز وصول آمنة قصيرة العمر وتجديد آمن، مع كلمات مرور مجزأة بـ Argon2 أو bcrypt. |
| الاتصال | HTTPS وTLS 1.2+ في جميع البيئات الممكنة، وعدم وضع أي أسرار في الشيفرة أو المستودع. |

استخدم migrations مرقمة وقابلة للتتبع لبناء قاعدة البيانات، ولا تنشئ الجداول يدوياً خارج migrations. أنشئ اختبارات للوحدات والقواعد المالية والصلاحيات والمسارات الأساسية، واستخدم معاملات قاعدة البيانات (**Transactions**) للعمليات المالية والحساسة.

## 4. الأمن والصلاحيات وإدارة الحسابات

طبّق مبدأ أقل الصلاحيات (**Least Privilege**) في الواجهة والخلفية وقاعدة البيانات. يجب أن تكون رسائل الخطأ مفهومة للمستخدم ولا تكشف تفاصيل تقنية، مع تسجيل داخلي آمن لأخطاء التشغيل اللازمة للمعالجة.

### 4.1 الأدوار الأساسية

| الدور | الوصف والصلاحيات الأساسية |
| --- | --- |
| مدير | صلاحيات كاملة على جميع الوحدات، بما فيها الإعدادات، المستخدمون، الصلاحيات، الإدارة، التعديل، الحذف المصرح، التقارير، الاعتمادات، وسجل التدقيق. |
| محاسب | وصول كامل إلى الإيرادات والمصروفات والمدفوعات والفواتير والإحصائيات المالية، وقراءة فقط للوحدات التشغيلية الضرورية للتحقق المحاسبي. لا يصل إلى إعدادات النظام أو إدارة المستخدمين إلا بصلاحية صريحة. |
| موظف حجوزات | إدخال خدمات العملاء وتعديلها ضمن الوحدات المصرح بها، والبحث عن العملاء وطباعة مستندات خدماته. لا يحذف سجلات مالية، ولا يدير المستخدمين أو إعدادات النظام. |

لكل وحدة صلاحيات دقيقة: **قراءة، كتابة، تعديل**. أضف أفعالاً حساسة منفصلة عند الحاجة مثل: حذف، اعتماد، إلغاء، تصدير، وطباعة. لا تمنح أي فعل حساس لمجرد وجود صلاحية قراءة أو كتابة.

### 4.2 إعدادات المستخدمين والصلاحيات

ضمن قائمة الإعدادات المنسدلة، أنشئ قسم «إعدادات المستخدمين والصلاحيات» ويحتوي على ما يلي:

| الخيار | السلوك الإلزامي |
| --- | --- |
| إنشاء حسابات موظفين | ينشئ المدير حساب موظف، ويربطه بموظف موجود أو ينشئ ملف الموظف أولاً. تُفرض كلمة مرور آمنة وتغييرها عند أول تسجيل دخول. لا تظهر كلمة مرور افتراضية في الواجهة أو السجلات. |
| تحديد الصلاحيات | تعيين دور: مدير أو محاسب أو موظف حجوزات، ثم منح أو سحب صلاحيات قراءة وكتابة وتعديل لكل وحدة. يجب أن تطبق الصلاحيات في الـ Backend على مستوى كل API Endpoint. |
| إلغاء حسابات موظفين | تعطيل الحساب ومنع دخوله فوراً مع الحفاظ على سجلاته التاريخية وسجل التدقيق. لا تحذف الحسابات ذات العمليات المرتبطة. |
| تعديل حسابات موظفين | تعديل اسم المستخدم، وإطلاق مسار آمن لتغيير كلمة المرور. لا تعرض كلمة المرور الحالية ولا تسترجعها كنص. |

فعّل قفل الحساب مؤقتاً عند تكرار محاولات الدخول الفاشلة وفق سياسة آمنة. تكون استعادة كلمة المرور عبر مسار آمن ومحدود الصلاحية، مثل رابط لمرة واحدة أو إجراء إداري موثق، ولا تستخدم أسئلة شخصية ثابتة أو إجابات حساسة صريحة داخل الشيفرة أو قاعدة البيانات.

## 5. قاعدة بيانات PostgreSQL: المخطط والعلاقات وقواعد البيانات

استخدم PostgreSQL بمخططات منطقية واضحة. اعتمد `uuid` مفاتيح رئيسية مولّدة عبر `gen_random_uuid()`، واستخدم `timestamp with time zone` للوقت التشغيلي، و`date` للتواريخ الخالصة، و`numeric(14,2)` للمبالغ المالية. لا تستخدم `float` أو `double precision` للمبالغ.

فعّل امتدادي `pgcrypto` و`citext` عند الحاجة. استخدم تسمية `snake_case` لأسماء الجداول والأعمدة والفهارس والقيود، مع بقاء النصوص في الواجهة عربية أو إنجليزية حسب إعداد اللغة.

### 5.1 مخططات PostgreSQL والجداول الأساسية

| المخطط | الجداول المطلوبة | الهدف |
| --- | --- | --- |
| `iam` | `users`, `roles`, `permissions`, `role_permissions`, `user_permissions`, `password_reset_tokens` | الحسابات، الأدوار، الصلاحيات، والتعطيل والاسترداد الآمن. |
| `core` | `customers`, `employees`, `agents`, `transport_companies`, `service_providers`, `system_settings` | البيانات المرجعية المشتركة للعملاء والموظفين والوكلاء والشركات والإعدادات. |
| `ops` | `service_orders` وجداول الخدمات المتخصصة | المعاملات والخدمات التشغيلية، مع فصل كل خدمة في جدول مستقل. |
| `finance` | `invoices`, `invoice_items`, `payments`, `payment_allocations`, `expenses`, `expense_categories` | الفواتير والتحصيل والمصروفات والتقارير المالية. |
| `audit` | `audit_logs`, `login_events` | سجل تدقيق غير قابل للتعديل من واجهة المستخدم، وتوثيق الدخول. |
| `reporting` | `dashboard_kpis_v`, `daily_finance_summary_v`, `top_services_v`, `employee_performance_v`, `visa_expiry_monitoring_v`, `invoice_balance_v` | Views مخصصة للتقارير ولوحة التحكم والحسابات المشتقة. |

### 5.2 جداول الهوية والصلاحيات

| الجدول | الحقول والقواعد الجوهرية |
| --- | --- |
| `iam.roles` | `id`, `code`, `name_ar`, `name_en`, `is_system`. الأدوار الأساسية: `manager`, `accountant`, `booking_officer`. |
| `iam.permissions` | `id`, `module_key`, `action`, `name_ar`. تدعم على الأقل: `read`, `create`, `update`, `delete`, `approve`, `cancel`, `export`, `print`. |
| `iam.role_permissions` | مفتاح مركب فريد من `role_id` و`permission_id` لمنع تكرار منح الصلاحية. |
| `iam.users` | `id`, `employee_id`, `username`, `password_hash`, `role_id`, `is_active`, `must_change_password`, `last_login_at`, `disabled_at`, `created_at`, `updated_at`. اسم المستخدم فريد وغير حساس لحالة الأحرف. |
| `iam.user_permissions` | استثناءات دقيقة للمستخدم: `user_id`, `permission_id`, `is_allowed`، مع تسجيل تدقيق إلزامي لكل تغيير. |
| `iam.password_reset_tokens` | `id`, `user_id`, `token_hash`, `expires_at`, `used_at`, `created_at`. لا تحفظ الرمز الفعلي، ويستخدم مرة واحدة فقط. |

### 5.3 جداول البيانات المرجعية

| الجدول | الحقول الإلزامية والعلاقات |

| `core.customers` | `id`, `customer_number`, `full_name`, `phone_number`, `passport_number`, `national_id_number`, `joined_on`, `referral_source`, `is_active`, `created_at`, `updated_at`. رقم العميل فريد ويولد تلقائياً. حقول الجواز والهوية اختيارية عند الحاجة. |
| `core.employees` | `id`, `employee_number`, `full_name`, `hired_on`, `job_title`, `is_active`, `created_at`, `updated_at`. رقم الموظف فريد، ويمكن ربطه بحساب مستخدم واحد. |

### 5.4 رأس المعاملة الموحد والجداول المتخصصة

أنشئ `ops.service_orders` كرأس معاملة مشترك فقط، وليس كنموذج موحد لجميع الخدمات. يحتوي كحد أدنى على: `id`, `service_number`, `service_type`, `customer_id`, `handled_by_employee_id`, `provider_id`, `status`, `price_amount`, `currency_code`, `notes`, `created_at`, `updated_at`, `created_by_user_id`, `archived_at`.

يكون `service_number` فريداً ويولد تلقائياً. يجب أن يرتبط كل سجل في `service_orders` بصف واحد فقط في **جدول خدمة متخصص واحد**، ولا تحفظ الحقول التشغيلية الرئيسية داخل `jsonb`. تنفذ طبقة التطبيق والتحقق وقاعدة البيانات هذا الشرط قبل اعتماد المعاملة.

أنشئ الجداول المتخصصة التالية. تحتوي كل منها على `service_order_id` كمفتاح رئيسي ومفتاح أجنبي إلى `ops.service_orders(id)`، ثم الحقول التفصيلية نفسها الواردة لاحقاً في قسم الخدمات:

| مجال الخدمة | الجداول المتخصصة المطلوبة |
| --- | --- |
| الحج والعمرة | `hajj_program_services`, `hajj_regular_services`, `umrah_program_services`, `umrah_regular_services` |
| الجوازات | `passport_attendance_services`, `passport_without_attendance_services` |
| تذاكر الطيران | `flight_ticket_services` |
| النقل | `international_bus_services`, `international_car_services`, `local_bus_services`, `local_car_services` |
| التأشيرات | `medical_visa_services`, `tourist_visa_services`, `work_visa_services`, `visit_visa_services` |
| الشحن والتخليص | `shipping_services`, `customs_clearance_services` |
| المعاملات الخاصة | `security_approval_services`, `medical_report_services`, `travel_insurance_services`, `hotel_booking_services` |

### 5.5 المالية والتدقيق والتكامل

| الجدول أو الـ View | القاعدة الإلزامية |
| --- | --- |
| `finance.invoices` | `invoice_number` فريد بصيغة `INV-YYYY-00001`، ويرتبط بالعميل والخدمة. يتضمن `issued_at`, `currency_code`, `total_amount`, `status`. يولد الرقم داخل Transaction مع حماية من التنافس. |
| `finance.invoice_items` | بنود الفاتورة مع الوصف والكمية وسعر الوحدة والإجمالي. يجب أن يطابق مجموع البنود إجمالي الفاتورة بعد أي تسويات موثقة. |
| `finance.payments` | سند دفع فريد يتضمن العميل والتاريخ والمبلغ والعملة وطريقة الدفع ورقم الحوالة أو رقم العملية عند انطباقها وحالة الاعتماد. لا تحذف دفعة معتمدة؛ تعكس بسند عكسي موثق. |
| `finance.payment_allocations` | يربط الدفعات بالفواتير ويمنع تطبيق مبلغ يتجاوز قيمة الدفعة أو الرصيد غير المسدد للفاتورة. |
| `finance.expenses` | يتضمن رقم المصروف والتاريخ والفئة والوصف والمستفيد والمبلغ والعملة وطريقة الدفع والمرجع وحالة الاعتماد والمنشئ. |
| `reporting.invoice_balance_v` | مصدر الحقيقة للمبلغ المتبقي: إجمالي الفاتورة ناقص مجموع الدفعات المعتمدة المطبقة عليها. لا يكون المبلغ المتبقي حقلاً يحرره المستخدم. |
| `audit.audit_logs` | `id`, `occurred_at`, `actor_user_id`, `actor_role_snapshot`, `action`, `module_key`, `entity_type`, `entity_id`, `request_id`, `ip_address`, `before_data_json`, `after_data_json`, `summary_ar`. لا تخزن كلمات مرور أو رموز أو أرقام جواز أو هوية كاملة. |

استخدم `currency_code` بقيد يقصر العملات على `SAR`, `YER`, `USD`، وتُعرض في الواجهة على هيئة ر.س ور.ي ودولار. طبّق `NOT NULL` و`UNIQUE` و`CHECK (amount >= 0)` و`CHECK (end_date >= start_date)` عند انطباقها. أنشئ فهارس على المفاتيح الأجنبية وحقول البحث المهمة: اسم العميل ورقم هاتفه وجوازه، رقم الخدمة، رقم الفاتورة، تواريخ الفواتير والمدفوعات والمصروفات، وحقل انتهاء التأشيرة.

طبّق نسخاً احتياطية مشفرة ومختبرة باستعادة دورية، مع فصل مستخدم migrations عن مستخدم التطبيق وتطبيق أقل الصلاحيات على مستخدم قاعدة البيانات.

## 6. قواعد عامة ملزمة لجميع الخدمات والنماذج

1. رتّب الحقول داخل كل نموذج **بالترتيب نفسه أدناه حرفياً**. لا تنقل حقلاً أو تدمج نموذجين أو تحذف قيمة من قائمة منسدلة.

1. تحتوي القوائم المنسدلة على القيم المذكورة نصاً فقط. لا تضف قيماً افتراضية أو عامة لا يطلبها هذا البرومبت.

1. رقم العميل يطلق تلقائياً وفريداً. عند اختيار عميل موجود، تملأ بياناته المتاحة مثل رقم العميل والهاتف ورقم الجواز عند توفره، من دون تعديل صامت لسجل العميل.

1. رقم الفاتورة تسلسلي وفريد على مستوى النظام كله بصيغة مثل `INV-2026-00001`.

1. المبلغ المتبقي في جميع الخدمات = السعر − المبلغ المسلّم. يحسب تلقائياً في الخلفية والواجهة، ولا يسمح بإدخاله يدوياً.

1. طرق الدفع التي تتضمن حوالة أو محفظة يجب أن تسمح بإدخال رقم الحوالة أو رقم العملية عندما ينص النموذج على ذلك.

1. كل خدمة يجب أن تسمح بالحفظ والتعديل ضمن الصلاحية، والأرشفة أو الحذف وفق سياسة الاحتفاظ، وطباعة سند إلكتروني منظم، والتصدير إلى Excel وPDF مع الحفاظ على ترتيب البيانات.

1. لا تفقد مدخلات النموذج عند فشل الحفظ. اعرض رسالة خطأ مفهومة قرب الحقل أو في أعلى النموذج من دون كشف معلومات تقنية.

1. يستخدم النظام العملات: **ر.س، ر.ي، دولار** فقط.

## 9. المالية

يكون قسم المالية مستقلاً ومنظماً، ولا يخلط الإيرادات والمصروفات والمدفوعات والفواتير في جدول واحد.

### 9.1 الإيرادات والمصروفات

اعرض إيرادات اليوم ومصروفات اليوم، مع فلاتر للفترة والعملات المصرح بها. وفّر تقرير PDF يومي للإيرادات، وتقرير PDF يومي للمصروفات. يجب أن تعكس الإيرادات الدفعات المعتمدة فقط، وأن تعكس المصروفات السجلات المعتمدة فقط.

### 9.2 المدفوعات

اعرض الدفعات المرتبطة بالعميل والخدمة والفاتورة، وبيّن وسيلة الدفع ورقم الحوالة أو رقم العملية عند انطباقه. ميّز بوضوح بين المبلغ الإجمالي والمدفوع والمتبقي. لا تسمح بدفعة تتجاوز الرصيد غير المسدد إلا بصلاحية اعتماد صريحة، وسبب موثق في سجل التدقيق.

### 9.3 الفواتير

كل خدمة تصدر فاتورة تحصل على رقم تلقائي متسلسل وفريد في النظام مثل `INV-2026-00001`. تعرض الفاتورة العميل والخدمة والمبلغ الإجمالي والمدفوع والمتبقي والعملـة وتاريخ الإصدار وحالة الفاتورة. يجب توفير معاينة وطباعة وتنزيل PDF رسمي متوافق مع RTL.

## 10. إعدادات المراقبة

### 10.1 الإحصائيات

اعرض مؤشرات: **أكثر الخدمات مبيعاً، أفضل العملاء، وأداء الموظفين** ضمن لوحة بيانات بمخططات تفاعلية قابلة للتصفية حسب الفترة الزمنية والوحدة الخدمية والعملة عند الحاجة. تحتوي كل مخططات على عنوان ووسيلة إيضاح وقيم مقروءة، ولا تعتمد على اللون وحده لإيصال المعنى.

### 10.2 سجل التدقيق

أنشئ شاشة «سجل التدقيق» للمدير أو لصلاحية تدقيق مستقلة. تسجل العملية: التاريخ والوقت، المستخدم، الدور، الإجراء، الوحدة، رقم السجل المرتبط، وملخصاً آمناً للتعديل. يجب تسجيل الدخول والخروج وإنشاء وتعديل وأرشفة السجلات والتغييرات المالية والصلاحيات والحسابات والإعدادات.

لا تسجل كلمات المرور أو رموز الاسترداد أو أرقام الوثائق كاملة. لا يمكن تعديل أو حذف سجل التدقيق من الواجهة.

### 10.3 التأشيرات قاربت الانتهاء

أنشئ شاشة مستقلة للتأشيرات التي قاربت على الانتهاء، وتعرض: العميل، رقم المعاملة، نوع التأشيرة، تاريخ الدخول أو الإصدار عند انطباقه، تاريخ الانتهاء، الأيام المتبقية، الحالة، ووسيلة التواصل المتاحة. تحسب تأشيرة العمرة لمدة 85 يوماً من تاريخ الدخول.

الحالات الافتراضية هي: «قريبة» عندما يتبقى من 8 إلى 30 يوماً، و«عاجلة» عندما يتبقى من 0 إلى 7 أيام، و«منتهية» عند تجاوز تاريخ الانتهاء. يكون الفرز تصاعدياً حسب الأيام المتبقية، مع فلاتر للحالة والنوع. يحتفظ المدير بإمكانية ضبط عدد أيام التحذير مستقبلاً من الإعدادات.

## 12. الهوية البصرية ونظام التصميم

استخدم خط **Cairo** في كامل النظام، ولا تستخدم عائلة خطوط بديلة إلا كخيار احتياطي تقني. استخدم وزن `400` للنصوص، و`600` للعناوين الفرعية، و`700` للعناوين الرئيسية والقيم المالية المهمة.

استلهم الهيكل البصري من الصورة المرجعية من حيث التنظيم: شريط جانبي نظيف، رأس علوي خفيف، بطاقات مؤشرات باستيل، بطاقات محتوى بيضاء، ومخططات داخل شبكة مرتبة. لا تنسخ أي اسم أو شعار أو نص أو أيقونة أو بيانات من المرجع؛ خذ منه التنظيم والإيقاع البصري فقط، وطبّقه بهوية سما اليمن للسفريات والسياحة.

| العنصر | مواصفات التصميم الإلزامية |
| --- | --- |
| الخلفية | `#F8F9FC` أو أبيض بارد قريب، مع مساحات بيضاء مريحة ومن دون نقوش أو زخرفة مزعجة. |
| الشريط الجانبي | يوضع في **يمين الشاشة** في العربية. لونه أبيض `#FFFFFF`، بحد أيسر خفيف `#EEF0F5` وظل بسيط. لا يكون كتلة بنفسجية مصمتة. |
| اللون الأساسي | بنفسجي ملكي `#7C3AED` مع تدرج محدود إلى `#A855F7` للزر الأساسي والعنصر المحدد فقط. |
| الحالة عند المرور | عند مرور المؤشر أو النزول على سطر قابل للتحديد في اللوحة اليمنى، يتحول السطر إلى `#F3E8FF`، والنص والأيقونة إلى `#6D28D9`، بانتقال خفيف لا يتجاوز `160ms`. |
| الحالة المحددة | عند النقر على السطر، يصبح محدداً بخلفية بنفسجية متدرجة من `#7C3AED` إلى `#A855F7`، ونص وأيقونة باللون الأبيض، مع مؤشر حافة أو ظل بنفسجي ناعم. يبقى واضحاً حتى تغيير الصفحة. |
| البطاقات | خلفية بيضاء، نصف قطر من `10px` إلى `14px`، حد `#EEF0F5`، وظل ناعم `0 4px 16px rgba(15, 23, 42, .04)`. |
| بطاقات المؤشرات | خلفيات باستيل هادئة: ليلكي، أزرق سماوي، خوخي، نعناعي، وأصفر دافئ. تحتوي كل بطاقة أيقونة خطية داخل مربع ملون بسيط. |
| النصوص | العناوين `#1F2937`، النص الثانوي `#64748B`، والقيم الرئيسية `#111827`. لا تستخدم تبايناً ضعيفاً. |
| الأيقونات | أيقونات خطية متجانسة تدل على العميل والموظف والفاتورة والمحفظة والمخطط والتأشيرة والإعدادات. لا تستخدم رسومات كرتونية أو صوراً كبيرة داخل لوحة التشغيل. |
| المسافات | اعتمد شبكة مسافات بمضاعفات `8px` وهوامش داخلية من `16px` إلى `24px`. لا تضع أكثر من إجراء أساسي واحد داخل المساحة البصرية نفسها. |

يجب أن تكون منطقة النقر لكل عنصر في القائمة كاملة، بارتفاع يتراوح بين `42px` و`46px`، ونصف قطر `8px`. تدعم العناصر لوحة المفاتيح وتظهر حالة تركيز بنفسجية واضحة. لا يفتح التمرير القائمة تلقائياً ولا يحوّل المرور إلى تحديد فعلي؛ التحديد يتم بالنقر أو بلوحة المفاتيح فقط.

## 13. هيكل التنقل

ضع التنقل الرئيسي في الشريط الجانبي الأيمن، بالترتيب الآتي:

| الترتيب | القسم | الصفحات أو المحتوى |
| --- | --- | --- |
| 1 | لوحة التحكم | مؤشرات، تنبيهات، ملخص مالي، آخر النشاطات، واختصارات عمليات يومية. |
| 2 | الخدمات | الحج والعمرة، الجوازات، تذاكر الطيران، النقل الدولي والمحلي، التأشيرات، الشحن والتخليص، المعاملات الخاصة. |
| 3 | الإدارات | إدارة العملاء، إدارة الموظفين، إدارة الوكلاء والشركات. |
| 4 | المالية | الإيرادات والمصروفات، المدفوعات، الفواتير. |
| 5 | إعدادات المراقبة | الإحصائيات، سجل التدقيق، التأشيرات قاربت الانتهاء. |
| 6 | الإعدادات | إعدادات المستخدمين والصلاحيات، إعدادات النظام. |

تكون الأقسام ذات الصفحات المتعددة قابلة للتوسيع. إذا كانت صفحة فرعية نشطة، يظهر القسم الأب بحالة هادئة مرتبطة، بينما تظهر الصفحة الفرعية المحددة بحالة أقوى. يجب إخفاء عناصر القائمة غير المصرح بها من الواجهة، مع استمرار منع الوصول إليها في الخلفية.

## 14. لوحة التحكم الرئيسية

استخدم شبكة مرنة من 12 عموداً على سطح المكتب مع مسافات بينية من `20px` إلى `24px`. تكون مساحة المحتوى في سطح المكتب مقسمة إلى عمود رئيسي عريض وعمود جانبي أضيق. في الشاشات المتوسطة والهواتف، تتحول تدريجياً إلى عمود واحد من دون تمرير أفقي غير ضروري.

### 14.1 الرأس العلوي

يتضمن الرأس: زر طي القائمة، عنوان «لوحة التحكم»، مسار تنقل، اختيار اللغة، زر الوضع النهاري أو الليلي، جرس إشعارات مع عداد، وصورة المستخدم وقائمة الحساب. لا تظهر بيانات حساسة في الرأس أو في قائمة الحساب.

### 14.2 شريط الإجراءات والفترة

ضع فلتر فترة موحداً «من تاريخ / إلى تاريخ»، وفلتر العملة عند الحاجة، وزر إجراء أساسي باسم «إضافة معاملة». يعرض الزر فقط أنواع الخدمات المصرح للمستخدم بإنشائها.

### 14.3 بطاقات المؤشرات

اعرض خمس بطاقات في الصفوف الأولى على سطح المكتب:

1. **المعاملات النشطة**.

1. **الإيرادات المحصلة اليوم**.

1. **المصروفات اليوم**.

1. **الفواتير غير المسددة**.

1. **التأشيرات قاربت الانتهاء**.

تعرض كل بطاقة القيمة والاتجاه مقارنة بالفترة السابقة عند توفر بيانات كافية. تكون البطاقة قابلة للنقر للانتقال إلى قائمة مفلترة بالسياق نفسه.

### 14.4 مكوّنات لوحة التحكم

| المكوّن | المحتوى والسلوك |
| --- | --- |
| حالة المعاملات | بطاقة واسعة لحالات: قيد المعالجة، قيد الانتظار، مكتملة، ملغاة. كل حالة تعرض عدداً وتفتح قائمة مفلترة عند النقر. |
| آخر العملاء | قائمة بآخر العملاء أو المعاملات تشمل الاسم ورقم العميل وآخر خدمة والحالة. لا تعرض رقم الجواز أو الهوية. تحتوي على رابط «عرض الكل». |
| الخدمات الأكثر طلباً | قائمة مرتبة بالخدمات الأعلى خلال الفترة، مع عدد المعاملات أو المبلغ المحصل حسب الفلتر، ورابط «عرض التفاصيل». |
| النظرة المالية | رسم خطي أو أعمدة للإيرادات والمصروفات عبر الفترة. لا تخلط عملات مختلفة في رسم واحد؛ استخدم فلتر العملة أو افصل الرسوم. |
| التأشيرات والتنبيهات | قائمة جانبية للتأشيرات القريبة أو العاجلة: العميل والنوع وتاريخ الانتهاء والأيام المتبقية، مرتبة من الأكثر إلحاحاً. |
| تقرير الأداء | بطاقة عريضة تقارن الإيرادات والمصروفات أو حجم المعاملات عبر اليوم أو الأسبوع أو الشهر. |
| توزيع الخدمات | رسم حلقي بسيط لتوزيع الخدمات حسب النوع، مع إجمالي واضح ووسيلة إيضاح نصية. |

تتصل كل بطاقة بمصدر بيانات فعلي من `reporting` أو استعلام معتمد ومحدد الصلاحية. لا تستخدم أرقاماً تجريبية في بيئة الإنتاج. حمّل بطاقات المؤشرات أولاً ثم الأجزاء الثانوية تدريجياً، واستخدم حالات انتظار هادئة وحالات فارغة ورسائل أخطاء مفهومة.

## 15. تجربة الاستخدام والأداء

يجب أن يستطيع الموظف تنفيذ البحث عن عميل، تسجيل خدمة، تسجيل دفعة، وطباعة فاتورة في أقل عدد عملي من الخطوات، دون إلغاء التحقق أو الصلاحيات أو التدقيق.

| المجال | متطلبات التنفيذ |
| --- | --- |
| النماذج | أقسام بعناوين واضحة، شبكة حقلين على سطح المكتب وعمود واحد على الهاتف، وشريط إجراءات ثابت للنماذج الطويلة يضم حفظ وإلغاء وطباعة عند انطباقها. لا تستخدم نافذة منبثقة لنموذج طويل. |
| التحقق | تحقق لحظي من الحقول المطلوبة والأرقام والتواريخ مع رسالة عربية مختصرة قرب الحقل. لا تمسح المدخلات عند فشل الحفظ. |
| البحث | بحث مؤجل لفترة قصيرة لمنع الطلبات المتكررة، وفهرسة في قاعدة البيانات، واقتراحات سريعة للعملاء. |
| الجداول | فلترة وفرز وترقيم صفحات من جانب الخادم. لا تجلب آلاف السجلات إلى المتصفح في طلب واحد. |
| العمليات المالية | منع النقر المزدوج، وإظهار حالة معالجة، وتنفيذ Transaction ذرية لمنع تكرار الدفعات وتضارب أرقام الفواتير. |
| التقارير | توليد PDF وExcel من الخادم، مع رسالة حالة واضحة وحفظ ترتيب البيانات والتنسيق RTL. |
| الرسوم والحركة | تجنب الصور الكبيرة والرسوم المتحركة الثقيلة والمكتبات غير الضرورية. لا تتجاوز الحركات البسيطة الحاجة الوظيفية. |

وفّر حالات تحميل، وحالات فارغة، وحالات خطأ لكل شاشة. أمثلة رسمية: «لا توجد فواتير ضمن الفترة المحددة»، و«تعذر حفظ البيانات حالياً. يرجى التحقق من الحقول ثم المحاولة مرة أخرى». لا تعرض Trace أو خطأ SQL أو اسم جدول أو تفاصيل تقنية للمستخدم.

عمليات الحذف والإلغاء وتغيير الصلاحيات تحتاج إلى مربع تأكيد رسمي يوضح أثر العملية. لا تؤدي عملية الحذف إلى كسر العلاقات المالية أو التدقيقية؛ استخدم التعطيل أو الأرشفة حيث يكون ذلك أنسب.

## 16. الطباعة والتصدير

كل خدمة لديها خيار لطباعة فاتورة أو سند إلكتروني وفق ما ورد في نموذجها. يجب أن تكون المستندات المطبوعة رسمية، متناسقة، ومهيأة للعربية وRTL، لا نصاً منسوخاً ولصقاً. تحتوي الفاتورة أو السند، حيث ينطبق، على اسم المكتب، رقم الفاتورة أو السند، بيانات العميل اللازمة، بيانات الخدمة، المبالغ والعملة، حالة الدفع، وتاريخ الإصدار.

يوفر النظام تصدير بيانات كل خدمة إلى Excel وحفظ التقارير بصيغة PDF، مع الحفاظ على ترتيب الحقول كما تظهر في النظام. لا تصدر حقول حساسة غير ضرورية لدور المستخدم أو للتقرير المطلوب.

## 17. معايير القبول النهائية

لا تعتبر المهمة مكتملة إلا بعد تحقق كل البنود الآتية:

- [ ] البرومبت الناتج هو نظام كامل حقيقي، لا واجهة تجريبية أو صفحات شكلية فقط.

- [ ] جميع الخدمات في القسم السابع موجودة منفصلة، وجميع حقولها وقوائمها وترتيبها مطابقة حرفياً لما ورد في هذا البرومبت.

- [ ] لا يتم دمج خدمات الحج أو العمرة أو الجوازات أو النقل أو التأشيرات أو الشحن أو المعاملات الخاصة في نموذج موحد.

- [ ] قاعدة البيانات هي PostgreSQL، وتُنشأ من migrations، وتحتوي على المخططات والجداول والعلاقات والفهارس والقيود وViews المحددة.

- [ ] تستخدم المبالغ `numeric(14,2)`، ولا يسمح بتعديل المبلغ المتبقي يدوياً، ولا يحدث تكرار للفاتورة أو السند تحت التنفيذ المتزامن.

- [ ] رقم العميل ورقم الموظف ورقم الخدمة ورقم الفاتورة وأرقام السندات فريدة وتولد تلقائياً.

- [ ] صلاحيات المدير والمحاسب وموظف الحجوزات مطبقة في الـ Backend على مستوى كل Endpoint، وليست في الواجهة فقط.

- [ ] واجهة تسجيل الدخول لا تكشف أسماء مستخدمين أو كلمات مرور أو أي بيانات اعتماد أو إجابات استرداد.

- [ ] واجهة العربية RTL بالكامل وتستخدم خط Cairo، وتدعم الإنجليزية LTR بصورة سليمة.

- [ ] الشريط الجانبي في اليمين، أبيض ونظيف، ويتحول السطر إلى بنفسجي فاتح عند المرور، ثم إلى بنفسجي متدرج بنص أبيض عند تحديده.

- [ ] لوحة التحكم تحتوي على المؤشرات وحالة المعاملات وآخر العملاء والخدمات الأكثر طلباً والنظرة المالية والتنبيهات وتقرير الأداء وتوزيع الخدمات، وتستخدم بيانات فعلية تخضع للصلاحيات.

- [ ] تظهر قائمة التأشيرات قاربت الانتهاء وتحسب تأشيرة العمرة تلقائياً لمدة 85 يوماً من تاريخ الدخول.

- [ ] تصدير PDF وExcel والطباعة يحافظ على RTL وترتيب البيانات ولا يعرض حقولاً حساسة خارج الصلاحية.

- [ ] سجل التدقيق يسجل العمليات الحساسة ولا يسمح بتعديله أو حذفه من الواجهة ولا يحتوي أسراراً أو وثائق كاملة.

- [ ] لا توجد نصوص أو أزرار غير مترجمة، ولا ازدحام بصري، ولا ألوان عشوائية، ولا تباين ضعيف، ولا تمرير أفقي غير مبرر.

## 18. توجيه التسليم للمطور أو للوكيل المنفّذ

ابدأ أولاً ببناء مخطط PostgreSQL وmigrations والصلاحيات والتدقيق وقواعد الفوترة، ثم أنشئ الوحدات التشغيلية والخدمات حرفياً وفق الحقول السابقة، ثم الإدارات والمالية والمراقبة، ثم لوحة التحكم والهوية البصرية. اختبر النظام بأدوار المدير والمحاسب وموظف الحجوزات، وتحقق من عدم تمكن أي دور من تجاوز صلاحيته.

اختبر المسارات اليومية: إنشاء عميل، تسجيل كل نوع من الخدمات، تحصيل دفعة، إصدار فاتورة، احتساب المبلغ المتبقي، متابعة تأشيرة العمرة، تصدير تقرير، وطباعة مستند. اختبر أيضاً سلوك القائمة اليمنى عند المرور والتحديد، والوضعين النهاري والليلي، والاستجابة على سطح المكتب والجهاز اللوحي والهاتف.
